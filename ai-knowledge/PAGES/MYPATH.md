## Purpose

The redesigned My Path defaults to a monthly study agenda. It puts courses available now first, then upcoming courses grouped by their start date; All provides the complete plan at a glance.

## Layout

| # | Section | What it contains | Desktop | Mobile |
|---|---|---|---|---|
| 1 | Fixed header | Month / All control, period picker, and Study Calendar entry point | Full-width bar outside the scroller (never moves, even during iOS rubber-band): tabs align left, period picker stays centred, calendar aligns right | Tabs and calendar share line one; centred picker moves to line two |
| 2 | Monthly agenda | Current courses, then upcoming courses grouped by start date | Centered reading column | Single-column agenda |
| 3 | Course card | Subject-colour plate or cover, Subject, Course title, type and total hours/date range; owned courses add a progress bar and study button | Horizontal card | Compact horizontal card; study button spans the full width |
| 4 | Navigation | Home, Courses, My Path, Profile | Bottom tab bar is the host's `BottomNav` (`src/host/components/BottomNav.tsx`), rendered by `MyPathTab` below the SDK box — the SDK does not know it exists | Same, with My Path active |

**App shell (native-iOS scroll):** the host's `.mypath-layout` (`src/index.css`) is `position:fixed; inset:0`, a flex column of the SDK box (`flex:1; min-height:0`) + `BottomNav` (static there), so there is no document scroll for Safari to bounce. Inside the box, `.mypath-root` fills it (`height:100%`, flex column): the header stays fixed and `.mp-scroll` is the only scrolling/bouncing element. The progress test panel sits outside the SDK box. Changing month remounts the scroller (`key={month}`) so it returns to the top. Trade-off: Safari's URL bar no longer collapses on scroll.

## Differences from the original mockup (tag `mockup-v1`)

Parity with the mockup was checked in #13 (criteria and accepted differences: `docs/mypath-sdk-plan.md` § เกณฑ์ครบเท่า prototype). The SDK differs in these ways:

- **No URL state:** Month/All and the selected month live in `<MyPath>` state (month starts at the month of **วันนี้**), so switching to All and back keeps the month; the segment switches without a router. ‹ › move within the axis and never touch the URL or history. A selected month that falls outside a recomputed axis is clamped to the nearest edge (the mockup used `?month=YYYY-MM`, pushed each month to history, and jumped back to TODAY's month).
- **วันนี้ comes from the host** (`today` prop); when omitted or malformed the SDK uses the Thai-time date from the device clock at render time. It drives the whole plan, not only the progress messages (the mockup's simulated today changed only the messages).
- **Plan maths is a pure function** (`packages/mypath/src/plan/buildPlan.ts`, copied from the mockup's `plan.ts`). The mock plan result is pinned by `tests/characterization/plan.test.ts` — a snapshot recorded from the mockup, now computed by the SDK from host fixtures; `tests/sdk/buildPlan.test.ts` covers วันนี้ and incomplete data. No `DAY_START`: a subject's first course with no earliest start date begins on วันนี้. Each `<MyPath>` computes its own plan in `MyPathProvider`, so several can render side by side.
- **All drag is controlled, emitted once:** dragging a course's lead grip (desktop) snaps to the nearest Monday (`snapToMonday`, 3.5-day edge). While dragging, the SDK shows a draft plan (`withCourseStartDate`, `packages/mypath/src/plan/timeline.ts`) as UI state with the axis frozen at its drag-start value; on release it calls `onPlanChange` once (ADR-0003, decided in #9) and then shows only what the host passes back — a host that does not echo the plan sees the bar snap back. Courses that follow the previous one move with it.
- **All opens scrolled to วันนี้** every time (the mockup restored the last scroll position across tab switches).
- **Course cards (Month) and course bars/cells (All) open Course Detail** (07, see `MYPATH-COURSE-DETAIL.md`) as `<MyPath>` state, not `?course=`; they are `role=button`, focusable, and open on Enter or Space. Clicking an All grip does not open it. On a Month card only the top part (`.mp-course-body`) is the button; the progress section with its study button is a sibling, so controls never nest (clicking the bar area itself opens nothing, unlike the mockup).
- **Course progress (09) reads host data:** owned Month cards show `CourseProgress` from `data.progress[courseId]` (missing or non-numeric = 0, clamped to 0–100) and **วันนี้** from the `today` prop; the rules are the pure `progressState(course, value, today)` in `packages/mypath/src/plan/progress.ts`, pinned on every branch by `tests/characterization/progress.test.ts` (snapshot recorded from the mockup, now computed by the SDK). The study button goes through `useStartCourse()` (shared with Course Detail: pins `startDate` via `onPlanChange` first when the course has none and does not follow the previous one, then calls `onStartCourse(courseId)`) and does not open Course Detail. No seed or simulated today in the SDK; the test panel is host-side.
- **Header tabs are buttons** that switch internal state (the mockup used React Router `Link`s); switching Month/All closes Course Detail and the Study Calendar panel.
- **CSS** lives in `packages/mypath/src/mypath.css`: every selector is under `.mypath-root` with an `mp-` class prefix (checked by `tests/boundary.test.ts`; All's `tp-` classes became `mp-tp-`, and `.mp-scroll.mp-tp-full` stands in for the mockup's `.path-scroll`); the primary blue is `--mp-primary`. Header/empty-state images and progress icons are bundled from `packages/mypath/src/assets/`.

## States & variants

- Month and All are the active tabs. Month is the default view; All renders the entire plan axis in the unified desktop calendar grid and has no period arrows. Year was removed by owner decision 2026-10-26. The Week tab was cut — the Monthly agenda covers it (owner decision 2026-10-24).
- On mobile, All places dated exam pills at each month's header. Course cards remain intact beneath them, and each month row expands naturally when it contains more events or course cards. Its desktop-only weekly-load graph is intentionally omitted on mobile.
- A mobile course card stretches to fill its month's row only when that course covers the entire calendar month; partial-month courses keep their compact card height.
- Available courses show in “วันนี้”; future courses are grouped under their start date. All monthly content is derived by `agendaFor()` — changing `today`, editing `hours`, flipping `owned`, or adding/removing events in host data re-renders both views with no view-specific edits.
- Both views highlight the month that contains วันนี้: Month colours the period label; All tints the month header on desktop and the whole month row on mobile.
- The desktop All weekly-hours row ("ชั่วโมงเรียน/สัปดาห์", 42px tall) is the final row of the shared, horizontally scrollable course table: one bar per calendar week on a shared absolute-hours scale (34px plot, 1px above the bottom, 5px/2px corner radius). The part within the Study Calendar budget is green, the part above it is red and stacked on the same bar, and a light dashed line marks the budget. A black (?) button opens a popover legend; hovering a bar shows planned/actual/over hours. Chosen 2026-10-27 from three variants (bars + plan line, diff from plan, monthly summary) — prototype kept on branch `prototype/weekly-hours-graph`. Desktop month columns use a 2.2 px/day minimum width.
- Desktop All shows exam/Mock flags **above the month header, outside the table**, so the eye moves from a flag straight down to its month. Flags are bottom-anchored: lane 0 sits on the table and overlapping dates stack upward; lanes are packed by an estimated px width at the minimum day width, so flags never overlap. Each flag's line ends in a half-circle marker tucked behind the table's top edge. The strip lives in the same horizontal scroller as the table (`.mp-tp-scroll`). Behind the flags is a flat Learn Anywhere sky (cyan → mint gradient, flat-bottom clouds in two parallax layers at 0.4× and 0.2× scroll via `--sx`, small swaying grass tufts that scroll 1:1 with the table); animations stop under `prefers-reduced-motion`. Mobile has no strip — month rows already carry their event pills. Chosen 2026-10-29 from variants A (original in-table row) / D (full-bleed, flags outside) / E (D + sky) — prototype kept on branch `prototype/mypath-milestone-sky`.
- All course bars (desktop and mobile) carry a subject-colour leading bar (left edge on desktop, white on owned courses). A course with **ตาม Course ก่อนหน้า** on its start date (`followPrevious`) drops the bar so a chain of follow-on courses reads as one continuous run; the rhythm option (`followPreviousWeeklyHours`) does not affect it. On mobile the bar is a thin horizontal bar along the card's top (inset 5px, 3px tall) and shows only in the month the course starts (continuation months omit it); it replaced the former full-width 5px top border (owner decision 2026-10-29).
- The monthly agenda leaves a 14px gap below the header. In the desktop All timeline, the subject-label column stays fixed while the month grid scrolls horizontally. On mobile All, the subject-column header sticks directly beneath the two-row Path header; its subject-colour markers are circular like desktop, and month labels left-align. The period picker has additional space around it to read as a separate, centred control.
- Rows follow the learner's enabled subjects (วิชาที่เรียน, `data.plan.calendar.subjects`, set in Study Calendar) in `data.catalog` order; user re-ordering is planned later. An enabled subject with no catalog course gets a grey row reading “ยังไม่มีคอร์ส” on desktop and only a grey header dot (blank column) on mobile. Exam/Mock events always show. The axis shrinks with the remaining courses (never before วันนี้'s month).
- With no enabled subject, Month and All replace their content with `PlanEmptyState`: a small hand-drawn arrow labelled "วางแผนด้วยตนเอง" pointing at the Study Calendar button, above a centred column of planning banners (max 768px, iPad-portrait width; more planning options will stack here). Today the column holds one Figma banner, "วางแผนการเรียนผ่านคณะที่เลือก" (node `69:19093`; background and cap bundled from `packages/mypath/src/assets/`). Its "วางแผนการเรียน กับพี่ไข่" button is inert (`title="เร็วๆ นี้"`) until the faculty-based planner exists.
- Course start/end ranges are derived: changing course weekly hours or catalog hours recalculates both Month and All. Study Calendar records learner availability and updates the shared capacity data without yet rescheduling course end dates.
- Course Detail is a bottom sheet on both desktop and mobile, easing smoothly into its final position from below and leaving quickly downward with a decelerating finish. It uses the same content: desktop places the course/CTA, schedule controls, and course summary horizontally; at 641–900px (including portrait iPad), it uses two columns with course title → summary → CTA on the left and schedule controls on the right; mobile stacks those panels vertically at full available width. The close button has equal top and right inset. Course-control labels share a 14px semibold style, and the custom 1–10 step slider draws its track, ticks, and thumb while retaining the numbers below. Changes go to the host via `onPlanChange` and update the estimated duration, plan, and timelines once the host passes the plan back. “ตาม Course ก่อนหน้า” is a themed checkbox aligned with the “วันเริ่มต้น” label; it uses the same schedule rule as an empty earliest-start date, disables the date picker without deleting its value, and restores that value when unchecked. The first course in a subject has no predecessor, so this checkbox is disabled with the same “ไม่มี Course ก่อนหน้า” tooltip as the weekly-rhythm control; the plan also treats a stale stored value as off. Desktop month columns have a 64px minimum width.
- Study Calendar is an approved panel with regular-day, weekend/holiday, school-break, and special-day controls; see `MYPATH-STUDY-CALENDAR.md`.
